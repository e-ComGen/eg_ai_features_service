# Сколько это стоит

Этот документ — про деньги. Сколько обращений к ИИ и сколько денег уходит на обработку одного товара. Считаем для разных сценариев, чтобы понять что выгодно, а что — нет.

## Сравнение с твоими SaaS-тарифами

Стандартный SaaS-маркап в индустрии — стоимость × 5-10.

| Пакет | Цена клиенту | Минус комиссия LavaTop (5%) | Минус твоя стоимость ИИ | Чистая маржа |
|---|---|---|---|---|
| Trial (3 карточки) | 0 ₽ | 0 | ~30 ₽ | -30 ₽ (это стоимость привлечения клиента) |
| Старт — 200 карточек | 990 ₽ | -49 ₽ | -800 до -1400 ₽ (типичный mix) | +540 ₽ маржа |
| Бизнес — 1000 карточек | 2990 ₽ | -149 ₽ | -4000 до -7000 ₽ | низкая или нулевая |
| Pro — 5000 карточек | 9900 ₽ | -495 ₽ | -20000 до -35000 ₽ | **отрицательная** ❌ |

⚠️ **Pro-тариф убыточен** на типичном миксе товаров. Это нужно фиксить до запуска. Варианты:

1. **Перевести дешёвые этапы на GigaChat / YandexGPT** (распределитель, судьи, знания ИИ). Они в 4-10 раз дешевле OpenAI для русскоязычных запросов. Vision и web_search оставить на OpenAI потому что у российских провайдеров нет аналогов.
2. **Ограничить бюджет на карточку** (`max_cost_credits = 50` → не больше $0.05 на одну карточку). Если этого не хватило — клиент получает частичный результат с пометкой.
3. **Двухтиповая тарификация**: «базовый» режим (только описание + знания, ~$0.02) и «продвинутый» (всё, ~$0.20). Клиент сам выбирает по характеру товара.
4. **Кэширование результатов** по похожим товарам — если уже искали «iPhone 15 Pro 256Gb», для второго клиента результат не пересчитываем.

## Где можно оптимизировать

1. **GigaChat / YandexGPT на распределитель/судей/знания** — нестратегические этапы, можно дешевле в 4-10 раз для русскоязычных запросов.
2. **Кэширование** по (отпечаток_товара, источник) — для популярных товаров (iPhone, AirPods, Nike) не пересчитываем заново.
3. **Батчевое извлечение** — одно обращение к ИИ на несколько характеристик сразу. Но это противоречит правилу «одно обращение = одна задача», поэтому опционально.
4. **Подкрутка порогов уверенности** — поднять до 85% → судью пропускаем чаще → экономия 30-50% обращений к судьям.
5. **Поиск по штрихкоду** (будущий этап 5) — для еды / электроники / косметики бесплатные API (Go-UPC, Open Food Facts) дают базовые характеристики совсем без ИИ.

## Что мониторить в работе

В каждом запросе сохранять в `audit_trail`:
- `total_llm_calls` — сколько обращений сделано
- `total_cost_credits` — сколько списано с баланса
- `stage_breakdown` — где сколько обращений (видно где основные траты)
- `early_exit_stage` — на каком этапе остановились благодаря cost-aware routing
- `judge_skips` — сколько раз обошли судью благодаря высокой уверенности
- `cache_hits` — когда добавим кэш, сколько было попаданий

Эти данные потом помогут реально настроить тарифы и понять где оптимизировать.
