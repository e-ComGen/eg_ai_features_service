# MANIFEST — FIX-7 variant-token contradiction guard (HARDEN)

## Проблема (rooted 2026-07-01, живой прогон Tier-A + in-process провенанс)
Источники (в первую очередь WEB_SEARCH) иногда возвращают значение, принадлежащее ДРУГОМУ
варианту той же линейки (со сравнительной/серийной страницы). Примеры живьём:
- «LG OLED**55**C4RLA» → «Диагональ, дюймы = **42**» (значение соседа 42″), при этом «см=138» верно.
- «Xiaomi Redmi Note **13**» → «Линейка = Redmi Note **14**».
Дефект **НЕДЕТЕРМИНИРОВАН** (перепрогон: то 42, то 55) — гоняться за источником бессмысленно.
После FIX-1 merge ранжирует по SOURCE_PRIORITY: WEB_SEARCH(2) > LLM_KNOWLEDGE(1), поэтому неверное
web-значение соседа перебивает ВЕРНОЕ значение, выведенное из имени модели.

## Инвариант INV-8 (ground truth = имя товара)
Имя товара АВТОРИТЕТНО для собственного варианта. Резолвнутое значение НЕ должно противоречить
вариант-дискриминатору (диагональ-размер, поколение линейки), ЯВНО присутствующему в
`product_name`. Противоречие ⇒ это утечка чужого варианта ⇒ **abstain (drop значение)**.
Источник-агностично (ловит web/llm/vision/любой), детерминировано, $0.

## Где (точка вставки)
`_reconcile_cross_field_contradictions(merged, targets, product_name)` в
`app/services/enrichment/pipeline.py:3796` — ДОБАВИТЬ параметр `product_name: str` (в конец).
Call-site `pipeline.py:5796` — передать `context.product_name` (проверить имя поля контекста;
если None/пусто → guard инертен). Guard = новый блок RULE-G ПОСЛЕ существующих RULE A/B/FIX-5,
перед `return`. Только DROP (никогда не добавляет/меняет значения).

## Правила (консервативные, минимум ложных срабатываний)

### RULE-G1 — display-size (диагональ)
- Применять ТОЛЬКО к target, чьё `name` матчит `диагональ.*дюйм` (целочисленная диагональ ТВ/монитор).
- `name_sizes` = множество целых из `product_name` в диапазоне **17..120** (реалистичные дюймы ТВ/монитора).
  (Диапазон отсекает модельные числа вроде C**4**, QN9**5**, годы, копейки.)
- Если `name_sizes` пусто → правило инертно (keep).
- Значение диагонали V: распарсить ведущее целое (снять `″`/`"`/`дюйм`/`inch`, пробелы).
  - V_int ∈ name_sizes → **KEEP**.
  - V_int ∉ name_sizes И name_sizes непусто → **DROP** (имя называет другой размер).
- НЕ трогать дробные диагонали смартфонов (6.67 и т.п.) — не integer-diagonal target.

### RULE-G2 — поколение линейки
- Применять ТОЛЬКО к target, чьё `name` матчит `^линейка\b|линейка\s+(?:мобильных|устройств|товаров)`.
  (НЕ трогать «Название модели (для объединения…)» / «…для шаблона наименования» — они ЛЕГИТИМНО
  эхо имени и НЕ должны фильтроваться.)
- Значение матчит `(?P<line>.+?)\s*(?P<gen>\d{1,3})\s*$` → line L + поколение N.
- Если `product_name` содержит L (нормализованно, регистронезав.), за которым следует целое M, и M≠N
  → **DROP** (линейка чужого поколения). Иначе KEEP.

Обе rule: value отсутствует/пусто → инертно. Идемпотентны. Логировать каждый DROP
(`logger.info("[Pipeline] FIX-7 RULE-G1/G2 dropped attr=%s value=%r (name=%r)", …)`).

## Arch/property инварианты (тесты)
- INV-8a: guard НИКОГДА не дропает value target'а, чьё name не матчит diagonal-дюймы / линейка-паттерн.
- INV-8b: при `product_name` без size-в-диапазоне-17..120 → ни один диагональ-value не дропнут.
- INV-8c: guard только УДАЛЯЕТ из результата, никогда не создаёт/не мутирует другие значения.
- INV-8d: идемпотентность (повторный прогон = тот же результат).
- INV-8e: сигнатурное изменение обратно-совместимо на call-site (context.product_name прокинут; None-safe).

## Acceptance (ВАЖНО — дефект флейки)
Акцептанс = **детерминированный оракул O1..O8 + arch-инварианты** (unit). Живой смоук НЕ может
доказать фикс (утечка недетерминирована — может не всплыть) → только подтверждающий, не блокирующий.
Регресс-гейт: НИ ОДИН из O5/O6/O7/O8 (no-FP) не должен дропнуться — ложный дроп реального спека хуже утечки.

  тяжёлая задача (FIX-8, не сейчас).
- M4 chuck-противоречие (аннотация «ключевой» vs поле «быстрозажимной») — домен FIX-5, отдельно.
