# Манифест: cpAiFeatures → eg_importer

**Дата:** 2026-06-21 · **Аудитория:** сессия/сервис eg_importer (Excel-обёртка, отчёт, выходной файл)

Этот документ — ориентир: что делает наш движок, что он тебе отдаёт, какие у нас
**реальные** метрики (честные, не розовые), и куда всё движется. Технический
пофайловый контракт — в [`API_CONTRACT_eg_importer.md`](API_CONTRACT_eg_importer.md).

---

## 1. Что это и бизнес-модель

**cpAiFeatures** — движок обогащения характеристик карточек **Ozon / WB**. На вход —
товар (название, бренд, EAN, категория, схема характеристик). На выход — заполненные
значения **с источником, уверенностью, evidence и авторитетным `value_id`**.

**eg_importer** — обёртка вокруг движка: принимает Excel клиента, парсит шаблон
маркетплейса, зовёт движок, **верстает выходной Excel + лист-отчёт, считает
заполнено/не-заполнено, формирует файл клиенту**.

**Бизнес:** done-for-you услуга «заполню карточки за вас», продаётся на **Авито**.
Клиент шлёт Excel → получает заполненный Excel + отчёт. Ноль интеграций на стороне
клиента. Монетизация — per-SKU, pay-per-use.

---

## 2. Разделение труда (строго)

| cpAiFeatures (движок) | eg_importer (этот сервис) |
|---|---|
| Извлекает значения из источников | Парсит Excel-шаблон МП клиента |
| Резолвит `value_id` по словарю Ozon (авторитетно) | Маппит значения в колонки по `attribute_id` |
| Даёт `source` / `confidence` / `evidence` | Считает % заполнено / не-заполнено |
| Классифицирует причину пустоты (`skipped.reason`) | Верстает отчёт (Источник/Уверенность/Откуда/Статус) |
| — | Формирует выходной файл, отдаёт клиенту |

**Принцип:** движок отдаёт ТОЛЬКО то, что достаётся у него (значение + value_id +
grounding-метаданные). Всё остальное — на eg_importer.

## 3. Что мы добавили в контракт (v2, 2026-06-21)

Раньше отдавали только `filled_features` (имя→value) + базовый `debug_info`.
**Добавили то, без чего нельзя собрать импорт и отчёт:**

- **`debug_info[feature].value_id` / `value_ids`** — авторитетный словарный ID Ozon.
  **Критично:** для enum-полей при импорте маркетплейс принимает ID, а не строку —
  без него значение может не сесть в карточку.
- **`debug_info[feature].attribute_id`** — стабильный числовой ключ маппинга (имена
  хрупкие, могут дублироваться/меняться).
- **`debug_info[feature].is_collection`** — значение массив или скаляр.
- **`debug_info[feature].semantic_type`** — color/weight/brand (подсказка вёрстки).
- **`skipped[feature] = {attribute_id, reason}`** — причина пустоты:
  - `platform_field` → 🔒 «ваше поле» (баркод/НДС/декларации — НЕ заполняем намеренно,
    это **не** недоработка);
  - `no_data` → «нет данных ни в одном источнике».

`source` / `confidence` / `evidence` были и раньше — это твои графы отчёта.

## 5. Философия качества (продавать именно это)

- **«Пусто честнее мусора»** — где нет надёжных данных, оставляем пусто и помечаем,
  а НЕ выдумываем. Галлюцинация в карточке = риск бана. conf=0.0 мусор отбрасывается,
  есть mud-гейт + adversarial-корроборация на llm_knowledge.
- **Авторитетный `value_id`** — значения привязаны к словарю МП → проходят модерацию,
  а не «отклонено».
- **Каждое значение проверяемо** — `source` + `evidence` (цитата/URL). Это защита от
  споров с клиентом и УТП («покажу, откуда каждое значение»).
- **Платформенные поля не трогаем** — баркод/НДС/декларации/ИКПУ это учётные данные
  продавца; помечаем 🔒, не считаем недобором.

## 6. Источники под капотом (что реально работает)

- **Бесплатные, всегда:** wb_card (CDN-карточка WB), competitor_rag (Qdrant
  ozon_products 1.69M точек), IceCat (brand-verified спеки по GTIN), web_search, vision,
  llm_knowledge, description.
- **Маркетплейс-пул через scrape.do** (флаг `LAMODA_SCRAPFLY_ENABLED`): живые —
  **lamoda** (одежда: Материал/Состав!), **sportmaster**, **zdravcity**, **exist**,
  **4lapy**. Это закрывает apparel data-пустыню **без подписочных скрейперов**.
- **Не пробиваются:** goldapple, vseinstrumenti (DataDome-hard); Ozon-карточка целиком
  (DataDome — scrape.do не берёт; данные Ozon достаём через competitor_rag, не скрейп).
- **Платный скрейпер — только scrape.do** (pay-per-credit; ZenRows/Scrapfly с месячной
  подпиской не используем).

**Средний:**

**Бизнес-вектор:** Авито done-for-you → повторная выручка через крупные каталоги и
агентства маркетплейсов; качество (value_id + evidence) = защита от конкурентов.

## 8. Что eg_importer должен делать (чек-лист)

1. Парсить Excel-шаблон экспорта Ozon/WB → собрать список targets (с `attribute_id`).
2. Звать движок (`BatchPayload`), получить `filled_features` + `debug_info` + `skipped`.
3. Маппить по **`attribute_id`** (не по имени): писать `value`, а для enum — **`value_id`/`value_ids`**.
4. Лист-отчёт по каждой характеристике: Значение | Источник | Уверенность% | Откуда(evidence) | Статус.
5. Статусы: ✔ (в filled) · ⚠ (`confidence < 0.6`) · — (`skipped.reason=no_data`) · 🔒 (`reason=platform_field`).
6. Сводка: % обязательных, % значимых, число ⚠ на ручную проверку, список пустых с причиной.
7. Risk-reversal: если обязательные < порога — флаг на доработку/возврат.

## 9. Честные оговорки

- Цифры §4 — на тест-наборах; реальное покрытие = per-batch отчёт.
- Ozon-классификатор `platform_field` консервативен → часть админ-полей придёт как `no_data`.
- `tokens_used = 0` (Tier-2 TODO) — биллинг по стоимости пока не из ответа.
- Маркетплейс-пул стоит денег (scrape.do кредиты на SKU) — включать осознанно под apparel/спорт/аптеку, на технике он near-zero (дублирует free-источники).
