# MANIFEST — FIX-8 resolve_value_id: unit-strip retry + numeric semantic guard (HARDEN)

## Проблема (rooted 2026-07-01, probe реального словаря Ozon)
`resolve_value_id` (`app/services/enrichment/strategies/dictionaries/ozon_loader.py:642`) для
«грязного» значения с единицей-суффиксом молча ПОДМЕНЯЕТ число на близкое-но-другое из словаря,
вместо чистого матча или abstain.

**Доказано probe (cat_id=15621050, type_id=95139, attr 5186 «Разрешение экрана», 472 enum):**
- `"2712x1220"`, `"2712×1220"`, `"2712 x 1220"` → все резолвятся ВЕРНО в id `972270457`. Значение В СЛОВАРЕ ЕСТЬ.
- `"2712×1220 pixels"` (с суффиксом) → НЕ None, а НЕВЕРНЫЙ id `970715447` = `"2640x1200"`.
  Точный/norm/fuzzy промахнулись из-за `pixels`, сработал семантический matcher (строки 679-692)
  и сматчил на близкое-но-ДРУГОЕ число.

Механизм: `_try_match_one_value` (строка 667) не снимает единицы-суффикс → промах → семантический
fallback `matcher.find_best_match` (строка 685) возвращает соседнее числовое значение. «Грязно-но-
верное» → «уверенно-неверное». Это фабрика галлюнов на числовых/размерных enum-полях.

## Инвариант INV-9 (семантика не смеет менять цифры)
1. Единица-суффикс (чистый шум: `pixels`, `px`, `точек`, `pixel`, `пикселей`) НЕ должна ломать точный
   матч: после снятия суффикса значение обязано резолвиться точно, если оно есть в словаре.
2. Семантический fallback НИКОГДА не возвращает кандидата, у которого набор ЦИФР отличается от набора
   цифр входного значения. Числа не совпали ⇒ **abstain (return None)**, а не «ближайшее».
Детерминировано, $0, источник-агностично.

## Где (точки вставки)
Функция `resolve_value_id`, `ozon_loader.py:642-692`. Два изменения, оба ВНУТРИ функции:

### FIX-8a — unit-strip retry (ПЕРЕД семантическим fallback, после list-unwrap блока ~строка 677)
Новый шаг между list-unwrap (строки 671-677) и semantic (679):
```
# Strip pure-noise measurement suffix and retry exact/fuzzy match.
stripped = _strip_unit_suffix(value)
if stripped is not None and stripped != value:
    vid = _try_match_one_value(stripped, values_list)
    if vid is not None:
        return vid
```
Хелпер `_strip_unit_suffix(value: str) -> Optional[str]` (модульного уровня, рядом с
`_unwrap_array_repr`):
- whitelist суффиксов ТОЛЬКО чистого шума: `pixels`, `pixel`, `px`, `точек`, `пикселей`, `пикс`.
  Матч регистронезав., как ОТДЕЛЬНОЕ trailing-слово (граница \b / конец строки; ведущий пробел/×
  сохраняется в теле). `"2712×1220 pixels"` → `"2712×1220"`.
- вернуть stripped (trim пробелов) если что-то снято, иначе None.
- НЕ трогать значения без такого trailing-суффикса (вернуть None → шаг инертен).
- НЕ снимать единицы, которые могут быть частью словарного значения (мм/см/дюйм/Вт/В/Гц/ГБ/Ah/Wh) —
  их в whitelist НЕТ (они бывают легитимной частью enum-строк; шум-суффиксы `pixels/px/точек` — нет).

### FIX-8b — numeric semantic guard (ВНУТРИ semantic-блока, строки 685-689)
Обернуть возврат семантического кандидата проверкой цифр:
```
matched = matcher.find_best_match(str(value), options)
if matched is not None and _digits_compatible(str(value), matched):
    for entry in values_list:
        if str(entry.get("value", "")) == matched:
            return entry.get("id")
```
Хелпер `_digits_compatible(query: str, candidate: str) -> bool` (модульного уровня):
- `q = набор всех групп цифр из query` (regex `\d+`), `c = то же из candidate`.
- Если q пусто (нечисловой запрос, напр. цвет/материал) → **True** (числовой guard НЕ применяется,
  семантика работает как раньше для нечисловых полей).
- Если q непусто → True ТОЛЬКО если мультимножество групп цифр совпадает (`sorted(q) == sorted(c)`).
  Разные числа ⇒ **False** ⇒ семантик abstain'ит.
- Логировать отказ: `logger.info("[ozon_loader] FIX-8b semantic abstain: query=%r matched=%r (digit mismatch)", value, matched)`.
